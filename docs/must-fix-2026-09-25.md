## MF-001 - Academic setup requests return HTTP 400

- **Observed:** After logging in as `admin@school.com`, the app redirected to `/admin/home`, but the browser console recorded six HTTP 400 responses while the admin dashboard/setup data loaded.
- **Impact:** Reproduces known K4. Academic Years, Classes, and Subjects may remain unavailable or stuck loading, blocking foundational setup workflows.
- **Status:** Open. Needs request URL/payload and Supabase response body captured, then repository/schema/RLS contract corrected.
- **Test case:** SU-01 login passed; setup loading failure observed immediately afterward.
- **Response body:** `{"code":"42703","message":"column rolepermission.permissionname does not exist"}`.
- **Blocked cases:** SU-02, SU-04, SU-06, SU-10, AD-01, AC-07 through AC-11, and any role workflow that depends on the permission bootstrap.
- **Proposed fix:** Apply `supabase/migrations/0030_reconcile_rolepermission_schema.sql` to the connected Supabase project, then reload the browser and rerun setup.
- **Academic Years button:** Present in `academic_year_list_page.dart` as `Add Year`, but not runtime-verifiable while the permission bootstrap leaves the screen in its loading state.

## MF-002 - Flutter semantic login tree duplicates controls

- **Observed:** The integrated browser initially exposed only Flutter's hidden `Enable accessibility` placeholder. After keyboard focus, the login form exposed duplicate semantic textboxes/buttons, and validation messages were not available in the accessibility snapshot.
- **Impact:** Makes reliable automated assertions for K2 difficult and may indicate a web accessibility/testability issue. The real keyboard login path still succeeded.
- **Status:** Open for investigation; distinguish Flutter release semantics behavior from an app-specific login form issue.

## MF-003 - Release build parser/type errors

- **Observed:** `_ReportCardView` was missing a closing brace, the staff form treated `createUser`'s returned user ID as a map, and class assignments passed a string where `UserRole.admin` was required.
- **Fix:** Corrected the class boundary, looked up the created staff row by returned `userid`, and used the `UserRole.admin` enum.
- **Status:** Resolved in source. `get_errors` reports no errors in the three affected files.
- **Note:** The `--pwa-strategy` message links to Flutter issue #156910 and is a deprecation warning, not a Dart source error.
